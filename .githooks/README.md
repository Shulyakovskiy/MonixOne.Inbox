# Git hooks

При первой обычной сборке любого `.csproj` или solution общий
`Directory.Build.targets` подключает `.githooks` через локальный
`core.hooksPath` и восстанавливает CSharpier из tool manifest репозитория.
До первой сборки hook ещё не активен. В CI, design-time build и архиве
исходников без `.git` установка пропускается.

`pre-commit` выполняет `dotnet csharpier check .` и не изменяет файлы.
Исправление форматирования: `dotnet csharpier format .`; затем проверьте diff
и добавьте нужные изменения в staging.

`.githooks/configure` не перезаписывает уже настроенный `.git/config`.
При параллельных первых сборках используются блокировка Git и до пяти
попыток с интервалом в одну секунду только при занятом `config.lock`.
Постоянные ошибки завершают сборку с ошибкой. Временный Git alias запускает
shell-скрипт и не сохраняется в конфигурации.

В существующем CI форматирование проверяется отдельно от локального hook.
Для запрета merge при ошибке проверки требуется настройка обязательного
успешного pipeline в GitLab или required status checks в GitHub.
